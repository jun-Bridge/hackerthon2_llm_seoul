# orchestrator/ — 턴 실행기 (조율자)

**두 코어를 아는 유일한 곳.** `chat/`과 `document/`는 서로를 모르고, 여기만 둘 다 안다.

왜 따로 두는가: 두 코어가 서로를 부르면 순환이 생기고, "승인 결과를 대화에 기록"·
"일괄 서식이 LLM을 호출" 같은 **걸치는 동작**이 어디 속하는지 매번 다투게 된다.
걸치는 일은 전부 여기로 모은다.

구현 예정
- `turn.py` — 한 턴의 수명. 컨텍스트 조립 → LLM 스트리밍 → 도구 호출 중계 → 제안 확정 → 턴 커밋
- `tool_loop.py` — 도구 호출 루프. **턴당 상한 필수.** 넘으면 강제 종료하고 그때까지의 제안을 제출
- `proposal_flow.py` — 제안 승인·거절 처리. 문서 코어에 반영 지시 → 결과를 대화 코어에 `system` 메시지로 기록
- `format_flow.py` — 일괄 서식. 채팅을 거치지 않지만 LLM 턴이므로 여기서 실행
- `events.py` — SSE 이벤트 발행. 이벤트 종류는 `docs/requirements.md`의 SSE 이벤트 계약 표가 정본
- `flush.py` — 플러시 트리거 판단

책임 경계
- 상태를 **소유하지 않는다.** 상태는 두 코어에 있다. 여기는 순서와 수명만 관리한다.
- 잠금 획득·해제도 여기서 한다 — 잠금의 수명이 곧 턴의 수명이므로.
