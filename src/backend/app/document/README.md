# document/ — 문서 코어 (캔버스)

대화와 나란히 선 별개의 코어. **대화를 모른다.** `chat/`을 import하지 않는다.

**저장 모델**: 대화 코어와 동일하다. Redis에 작업 사본을 두고 거기서 편집하다가,
트리거(제안 승인 · 편집 후 debounce · 명시 저장 · 다운로드 · 세션 이탈)마다
Postgres에 **통째로 덧씌운다.** 부분 병합 없음 — 작업본이 정답.

**승인 모델**: LLM은 쓰기 권한이 없다. 도구 호출은 제안 버퍼에 쌓이고,
diff를 사용자에게 보인 뒤 **적용**을 눌러야 작업본에 반영된다.

구현 예정
- `core.py` — 줄 CRUD. 조회·교체·삽입·삭제·순서 유지. Redis 작업본에 대해 동작
- `store.py` — Redis 복원(없으면 Postgres에서 적재) · dirty 표시 · Postgres 플러시
- `proposal.py` — 제안 버퍼 적재, 제안 적용 결과 계산, TTL 만료 처리
- `diff.py` — 현재 문서 vs 제안 결과 비교. 추가/삭제 단위로 표현
- `history.py` — undo/redo 스냅샷 스택. 깊이 상한, 새 편집 확정 시 redo 비움.
  **LLM 편집 적용 직전에 반드시 스냅샷을 남긴다**
- `lock.py` — 편집 잠금. LLM 생성 중 + 제안 대기 중 잠금. **TTL 자동 해제 필수**
- `markdown.py` — 블록 ↔ 마크다운 직렬화. `.md` 내보내기
- `format_service.py` — 일괄 서식(strip/apply). 결과는 다른 편집과 같이 제안으로 나간다
- `service.py` — 위를 묶은 진입점. LLM 도구와 사용자 편집 API가 **같은 경로**로 들어온다

원칙
- 요청마다 복원한다. 상주 객체를 두지 않는다.
- **블록 = 마크다운 한 줄.** 빈 줄도 블록이다. 문서 = 줄을 order 순으로 개행 이어붙인 것.
  diff의 단위와 편집의 단위가 같아진다.
- 줄은 안정적인 **id**로 가리킨다. 줄 번호나 문자 offset을 쓰지 않는다 — 사용자가 한 줄만 넣어도 전부 밀리기 때문.
- LLM이 쓰든 사람이 쓰든 통로는 하나. 두 경로가 갈라지면 잠금·정합성이 깨진다.
- **승인 없는 변경 없음.** 이 코어를 거치지 않고 문서가 바뀌는 경로는 존재하지 않는다.
